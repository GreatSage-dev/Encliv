How Encliv Works

Spot violations before they hit chain

Agent Request

AI agent sends a signed transaction request with ECDSA identity proof and incrementing nonce

→

TEE Policy Check

Inside the sealed enclave: verify caller → read on-chain policy → evaluate spend caps, allowlists, time windows

→

Sign or Refuse

Approved requests are signed and broadcast to chain. Violations produce a structured refusal with reason code

Security Features

More than a wallet guard

In-Enclave Keygen

Private key generated inside the TEE at boot using hardware entropy. Never imported, exported, logged, or exposed to any external process.

On-Chain Policy

Spend caps, allowlists, and time windows stored on-chain in EnclivPolicyRegistry. Publicly verifiable and tamper-evident.

Caller Authentication

ECDSA signature recovery verifies every request comes from the registered agent owner. Impersonation is cryptographically impossible.

Replay Protection

Incrementing nonces bound to the enclave address prevent captured requests from being resubmitted — even after TEE restart.

On-Chain Spend Tracking

Spend counters live on-chain, not in TEE memory. Enclave restarts cannot silently zero your spend counters or bypass caps.

Multi-Agent Registry

Any agent can register with its own independent policy. Encliv is infrastructure, not a single-use wallet — designed for fleet-scale deployment.
